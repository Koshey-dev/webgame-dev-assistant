# Ассистент разработчика веб-игр

Чат-ассистент для разработчика HTML5-игр: отвечает, что требуют игровые площадки
(Яндекс Игры, VK Игры, Одноклассники, CrazyGames, Poki, Playgama, GamePush, Y8,
GameDistribution, itch.io, Playdeck), с источниками и дословными цитатами
официальных страниц. Про сам проект отвечает команда `/help` — по этой
документации и данным git, которые ассистент получает через MCP.

Проект — сдача недели 7 курса AI Challenge (дни 31–35). День 31: ассистент
разработчика — RAG по документации проекта, MCP с git-веткой, команда `/help`.

## Что умеет

- **Вопросы о требованиях площадок.** Вопрос переписывается в поисковый запрос
  (с учётом истории чата), ищутся карточки требований, официальные страницы и
  заметки «Мой опыт». Ниже порога близости ответ «в базе этого нет» пишет код,
  а не модель. Под ответом — источники: площадка, раздел, дата сверки, цитата и
  ссылка.
- **`/help <вопрос>`** — вопрос о проекте: структура, модули, запуск, данные.
  Код всегда берёт текущую ветку у MCP-сервера git (`git_branch`), документы
  ищутся в базе «Проект» (README и `docs/`), остальные git-инструменты
  (`git_status`, `git_log`, `list_files`) модель вызывает сама, если нужно.
- **`/platforms`** — какие площадки в базе, сколько карточек и страниц, когда
  сверяли. **`/model`** — какая модель отвечает.
- **Выбор модели:** локальная в Ollama, DeepSeek или «свой API» — любой
  OpenAI-совместимый сервис; его адрес, модель и ключ хранятся только в
  браузере и уходят с каждым запросом.

## Три базы

| База | Что внутри | Где лежит |
|------|------------|-----------|
| Площадки — карточки | 852 факта: требование своими словами, дословная цитата, URL, дата сверки | `knowledge/<площадка>.md`, в git |
| Площадки — страницы | тексты официальных страниц требований (85 страниц) | `data/assistant.db`, собирает сервер |
| Мой опыт | чек-листы разработчика из своих проектов | `data/notes/*.md`, только на сервере |
| Проект | README и `docs/` | в git |

Карточки — проверенная основа: каждая цитата сверяется с текстом страницы
кодом (`py -m app.cards check`), не нашлась — карточка не годится. Карточки в
GitHub правит только автор; сервер их не меняет, а сырые страницы собирает сам.
Тексты чужих документаций в git не попадают — только реестр источников
`sources.toml` и свои формулировки с короткими цитатами.

## Запуск

Нужны Python 3.12+, git и Ollama с моделью эмбеддингов.

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
ollama pull embeddinggemma:300m-qat-q8_0
ollama pull qwen2.5:1.5b                 # локальная модель (LOCAL_MODEL)
cp .env.example .env                     # ключ DeepSeek и настройки
python -m app.crawl                      # собрать официальные страницы
python -m app.cards check                # сверить цитаты карточек со страницами
python -m app.rag build                  # собрать индекс
python -m uvicorn app.main:app --port 8010
```

Чат открывается на `http://127.0.0.1:8010/`.

## Выкатка на сервер

Сервер — релиз, а не рабочая копия: на нём стоит git-тег из GitHub, правок на
месте нет. Выкатка нового шага:

```bash
cd /opt/webgame-dev-assistant
git fetch --tags && git checkout day31
deploy/setup.sh                              # зависимости, страницы, сверка карточек, индекс
sudo systemctl restart webgame-assistant
```

Первый раз дополнительно: клон в `/opt/webgame-dev-assistant`, `.env` (режим 600),
служба из `deploy/webgame-assistant.service`, блок Caddy из `deploy/Caddyfile.webgame`
(пароль чата — basic auth Caddy, хеш через `caddy hash-password`).
«Мой опыт» кладётся в `data/notes/` отдельно, в git его нет.

## Настройки (`.env`)

| Переменная | Что задаёт | По умолчанию |
|------------|------------|--------------|
| `DEEPSEEK_API_KEY` | ключ DeepSeek | — |
| `DEEPSEEK_MODEL` | модель DeepSeek | `deepseek-flash` |
| `LOCAL_MODEL` | локальная модель в Ollama | `qwen2.5:1.5b` |
| `OLLAMA_URL` | адрес Ollama | `http://127.0.0.1:11434` |
| `EMBED_MODEL` | модель эмбеддингов | `embeddinggemma:300m-qat-q8_0` |
| `DEFAULT_MODEL` | модель по умолчанию в чате: `local`, `deepseek` | `deepseek` |
| `RAG_THRESHOLD` | порог косинуса для «в базе этого нет» (подобран контрольным набором) | `0.54` |
| `LLM_PROXY` | SOCKS-прокси для облачных моделей | — |
| `WDA_DATA` | папка данных сервера | `data/` |
| `WDA_REPO` | репозиторий, который видит MCP git | корень проекта |

## Структура

| Путь | Что это |
|------|---------|
| `app/main.py` | FastAPI: чат, API чатов, MCP-сервер git на `/mcp/git` |
| `app/answer.py` | ход ассистента: переписать запрос, поиск, порог, ответ модели, источники; `/help` с MCP |
| `app/rag.py` | резка по разделам, эмбеддинги, индекс, поиск |
| `app/crawl.py` | сбор официальных страниц из `sources.toml` |
| `app/htmltext.py` | основной текст страницы из HTML в markdown |
| `app/cards.py` | разбор карточек и сверка цитат со страницами |
| `app/providers.py` | модели: Ollama, DeepSeek, свой API |
| `app/mcp.py` | MCP по Streamable HTTP: сервер и клиент без SDK |
| `app/gittools.py` | MCP-сервер git: `git_branch`, `git_status`, `git_log`, `list_files` |
| `app/config.py` | пути и настройки из окружения |
| `app/db.py` | схема SQLite |
| `web/` | чат: `index.html`, `chat.js`, `chat.css` |
| `knowledge/` | карточки требований по площадкам |
| `sources.toml` | реестр официальных источников |
| `docs/` | архитектура, API, схема данных |
| `scripts/gen_docs.py` | генерация `docs/api.md` и `docs/data.md` из кода |
| `deploy/` | служба systemd и блок Caddy для сервера |
| `tests/` | pytest |
